# Poker Clock

A multi-league poker tournament clock with player check-in, bust-out tracking, and exports.

**Stack:** Next.js 15 (App Router) · TypeScript · Tailwind CSS v4 · Drizzle ORM · Neon Postgres · Clerk · Zod · ExcelJS

## Quick start

1. **Install:** `npm install` (Node 20 or later).
2. **Create a Neon project.** Copy both connection strings: the pooled one goes in `DATABASE_URL`, and the direct one goes in `DATABASE_URL_UNPOOLED`.
3. **Create a Clerk application.** Copy the publishable key and the secret key.
4. **Configure the environment:** `cp .env.example .env.local` and fill in the values. Also copy the database URLs into `.env`, because drizzle-kit and the seed script read `.env`.
5. **Migrate:** `npm run db:migrate`
6. **Become a platform admin:** sign up once at `/sign-up`, find your user ID in the Clerk dashboard (it starts with `user_`), and add it to `PLATFORM_ADMIN_USER_IDS`.
7. **Optional demo data:** `SEED_ADMIN_USER_ID=user_xxx npm run db:seed` creates two leagues, five venues, 20 players and one tournament per venue. It prints each tournament's public URL.
8. **Run:** `npm run dev`, then open `/admin`.

**Design preview without a database:** `/preview` (development only) shows the TV display with a simulated tournament, so you can check the layout and test sounds.

## Deploying (Vercel)

* Set every variable from `.env.example` in the project settings.
* Set `NEXT_PUBLIC_APP_URL` to your **production** domain over https, for example `https://clock.yourleague.com`. QR codes are hidden rather than generated if this is localhost, plain http, or a `*.vercel.app` preview URL. Set `ALLOW_VERCEL_APP_URL=true` only if your permanent domain really is a `vercel.app` address.
* In Clerk, add the production domain and switch to production keys.
* Run `npm run db:migrate` against production as part of each release. Migrations only add to the database. Never use `drizzle-kit push` or reset production.

## How it works

### Who can do what

| Role | How it's granted | Can |
|---|---|---|
| Platform admin | `PLATFORM_ADMIN_USER_IDS` or the `platform_admins` table | Create leagues, act as admin in any league |
| League admin | `league_memberships.role = admin` | Everything in their league: venues, staff, players, tournaments, structures, exports, corrections |
| Venue staff | `league_memberships.role = staff` plus a `venue_memberships` row | Per venue, with separate switches for check-in, eliminate, clock, manage players and export |
| Public viewer | Knows the six-character code | View the clock only |

Every server action and route handler calls `src/lib/auth.ts`. Those helpers load the record (a tournament, for example), read **its** league and venue from the database, and check the user's memberships. A league ID sent by the browser is never trusted on its own. Records in another league return the same "not found" response as records that don't exist, so IDs can't be probed.

### Tenant isolation in the database

Every tenant-owned table has a `league_id`. Child tables reference their parents with **composite foreign keys**, for example `registrations (player_id, league_id) → players (id, league_id)`. Postgres therefore rejects any cross-league link even if application code has a bug. Partial unique indexes allow only one active check-in and one active elimination per registration. Corrections mark the old record as undone rather than deleting it.

### The clock

* `tournament_timer_state` has one row per tournament. Each clock action locks only that tournament's row (`SELECT … FOR UPDATE`), applies the change, and increments a version number. Other tournaments are never blocked or touched.
* `src/lib/timer.ts` contains one pure function that the server and every browser both use. Given the stored state and the current time, it applies elapsed level changes. This is how levels advance automatically without a scheduled job, and why every screen shows the same thing.
* Displays poll `/api/tournament/[code]/state` every 2 seconds. Each response includes the server's time, so the display corrects for its own clock being off. Between polls the display keeps counting locally, and it re-syncs right away after a reconnect, tab switch, or refresh. The structure is ready for Pusher, Ably, or Neon logical replication if you want instant pushes. The staff device that made a change refreshes immediately.
* After the last level, the clock enters an explicit "end of structure" state. It never wraps back to level 1.

### Sounds

Sounds are generated by the browser with the Web Audio API. There are no audio files and no third-party services. There are four distinct sounds: the 1-minute warning, level change, break start, and break end. Spoken blind announcements are optional.

Each alert has a key made from the tournament code, an alert-cycle number, and the alert type. A device keeps its played keys in `localStorage`, so a refresh, reconnect, or duplicate poll never replays an alert. A device that connects after the 1-minute mark won't play a stale warning. Staff screens show alerts visually but don't claim them, so a TV in the same browser still plays them.

Each device has its own settings under the speaker icon: turn sound on for the TV and off for phones. The tournament also has a setting that turns break alerts on or off. Browsers block sound until someone taps the page, so the display shows a "Tap to turn on sound" button until then.

### Exports

* **One tournament:** `/api/exports/tournament/:id?format=csv|xlsx&history=0|1`. Requires league admin, or staff with the export permission.
* **Bulk:** `/api/exports/league/:leagueId?from=YYYY-MM-DD&to=YYYY-MM-DD&format=…`. League admins only. Produces one file per tournament, bundled as a ZIP.
* Each row has: registration time, check-in time and who checked the player in, status (including no-shows), finishing position, elimination time and who recorded it, the blind level at the time of elimination (captured when the elimination is saved), time played, and corrections.
* Times are shown in the venue's time zone. Cells are protected against spreadsheet formulas, and every download is written to the audit log.

## Tests

```bash
npm run typecheck
npm test                      # unit tests: timer engine, export format, codes, URL guard, time zones

# Acceptance tests run the real server actions against Postgres.
# WARNING: they DROP the public schema. Use a scratch database only.
TEST_DATABASE_URL=postgres://user:pass@localhost/scratch npm run test:integration

# Database-level isolation checks (run on a freshly migrated scratch database):
psql "$SCRATCH_URL" -f scripts/verify-isolation.sql
```

How the acceptance criteria are covered:

| # | Criterion | Where |
|---|---|---|
| 1–3 | Leagues are independent and players don't leak | integration "tenant isolation", `verify-isolation.sql` [1–3] |
| 4–5 | Clocks run independently; pause and reset are isolated | integration "clocks", unit "two tournaments are independent states" |
| 6–7 | Warning fires once; level-change sound | `use-tournament-clock.ts` alert keys. **Test by hand on a real TV** (see below) |
| 8, 13 | Displays are consistent; refresh doesn't reset | integration "public snapshot…", unit "auto-advances deterministically" |
| 9–10 | Check-in and elimination with timestamps; correct counts under concurrent use | integration "duplicate concurrent check-ins", "concurrent eliminations" |
| 11 | QR access grants no staff rights | Public routes are read-only; middleware and actions require Clerk |
| 12 | Cross-league reads and writes are rejected | integration "cannot read or write another league's tournament" |
| 14 | History is kept | integration "closing and creating new tournaments keeps history" |
| 15 | Matches the screenshot | `/preview`. Compare against your reference image |

### Manual checks before going live

1. Open the TV display on the actual TV or browser, tap **Tap to turn on sound**, and use the speaker menu to test all four sounds.
2. Start a tournament with a 2-minute level. Confirm the 1-minute warning plays exactly once. Refresh during the last minute and confirm it doesn't replay. Confirm the level-change sound plays when the level rolls over.
3. Run two tournaments side by side in two windows. Pause one and confirm the other keeps running.
4. Scan the QR code with a phone that isn't on the venue Wi-Fi and confirm it opens the production domain.

## Project layout

```
src/
  actions/      server actions (all authorization happens inside each one)
  app/          routes: /tournament/[code] (public/TV), /admin/**, /api/** (polling + exports)
  components/   clock display, audio, staff console, admin forms
  db/           Drizzle schema and Neon client
  lib/          timer engine, auth helpers, validation, export formatting
  server/       queries, timer state persistence, export generation, QR
drizzle/        SQL migrations
scripts/        seed, isolation checks
tests/          unit and integration tests
```

## Known limitations

* No reference screenshot was available while building this, so the display follows the written spec. Compare it with `/preview` and adjust spacing in `clock-display.tsx`.
* PDF export (listed as optional) is not implemented. CSV and Excel are.
* Blind structures belong to each tournament. New tournaments can copy the structure from any earlier tournament in the same league instead of picking from saved templates.
* Staff are added by email, and that person must already have signed up. No invitation emails are sent.
